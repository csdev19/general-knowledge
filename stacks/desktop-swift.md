# Stack: Swift desktop app (SwiftUI menu bar + AppKit panels)

A native macOS app: SwiftUI for the menu bar overlay and settings, AppKit for anything that
lives on the desktop (borderless panels, event monitors, activation), product code in a local
SwiftPM package with one `<Feature>{Domain,Application,Infrastructure,UI}` target set per feature,
the Xcode project generated by XcodeGen, releases as a signed and notarized DMG with Sparkle.

Written from one app in active development on this stack (a desktop-pets app) and its release
pipeline; the recipe grows as the app does. The template repository that starts a new app on this
stack points here.

## Assembly notes

- **XcodeGen owns the project.** `project.yml` is committed, `*.xcodeproj` is not. Run `xcodegen`
  after cloning, after editing `project.yml`, and after adding files under the app target; files
  added under the package need nothing.
- **Tests without Xcode.** Domain, application and adapter tests run with
  `swift test --package-path <package>` in seconds — no simulator, no app host. Keep UI targets
  thin so almost everything is testable that way.
- **Generated assets are committed, and a test keeps them honest.** When a build-time tool
  produces resources (sprite atlases, metadata), commit its output and add a test that
  regenerates into memory and compares byte for byte, so an edited source without a regenerated
  output fails the suite. Write PNGs with a deterministic encoder rather than ImageIO, whose
  bytes can change between macOS releases.
- **One instance per bundle id.** Menu bar apps set `LSMultipleInstancesProhibited`; a second
  copy started from Xcode exits at once with *Finished running*. Build probes under a separate
  bundle id (see the lifecycle page) and never launch the app from an agent session while the
  developer runs it from Xcode.
- **Click smoke test.** Keep `scripts/click-smoke.sh` (build under a smoke id, launch by pid,
  one synthetic click on a window, grep the `input` log) and run it before merging changes to
  windows, events or launch. It is the only automated check that catches silent input failures.
- **Sandbox and permissions.** Mouse-down global monitors work sandboxed without a prompt; key
  monitors need accessibility, and the supported sandboxed path for keys is `CGEventTap` with
  Input Monitoring. Verify permission behaviour on a Mac that has never seen the app.
